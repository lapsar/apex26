# APEX '26 — бриф на доводку 3D-модели болида

Это задание для отдельного чата. Цель — довести low-poly модель болида F1 в файле-крутилке
`car-preview.html`. Готовую крутилку я приношу обратно в основной чат, там модель встраивается в игру.

---

## 1. Контекст проекта

**APEX '26** — браузерная гонка F1. Один самодостаточный HTML-файл, весь код инлайн, работает офлайн.
Русский интерфейс. Тестируется на: iPhone 16 Pro Max, iPad mini 5, **старый iPad 5** (слабое звено), MacBook.

Модель должна быть **своя, процедурная (собранная из примитивов в коде)**. Причины:
- никаких внешних файлов (.glb/.obj/текстур) — игра остаётся одним HTML;
- чистая лицензия — **нельзя** использовать чужие модели и **нельзя** наносить реальные логотипы
  (FIA, Pirelli, F1, названия команд и спонсоров). Рефы можно использовать только как ориентир формы.

Текущее состояние: модель уже переработана под современный F1 2026 (граунд-эффект). Осталась доводка форм.

## 2. ЖЁСТКИЕ ограничения движка

- **three.js r128** (именно эта версия). Из неё **недоступны**:
  - `THREE.CapsuleGeometry` (появилась в r142) — не использовать;
  - `THREE.OrbitControls` — не подключается, орбита в крутилке написана вручную;
  - современные `colorSpace`-свойства — в r128 это `outputEncoding = THREE.sRGBEncoding`.
- Доступно и безопасно: `BoxGeometry`, `CylinderGeometry`, `SphereGeometry`, `ConeGeometry`,
  `TorusGeometry`, `RingGeometry`, `PlaneGeometry`, `LatheGeometry`, `ExtrudeGeometry`, `BufferGeometry`.
- Материалы: `MeshStandardMaterial` (основной), `MeshBasicMaterial` (для светящихся мелочей).
- Никаких загрузок по сети внутри модели (шрифты/текстуры/HDRI). Текстуры — только процедурные на canvas.

## 3. КОНТРАКТ МОДЕЛИ (это нельзя менять — иначе не встанет в игру)

Игра вызывает функцию и получает `THREE.Group`:

```js
makeCar(colorHex, num, simple) -> THREE.Group
```

- `colorHex` — цвет команды (строка `#RRGGBB`), красит кузовные детали;
- `num` — стартовый номер пилота (для таблички с номером);
- `simple` — `true` для всех болидов ИИ (упрощённый LOD), `false` только для болида игрока.

### 3.1. Ориентация и точка отсчёта

| Параметр | Значение | Почему важно |
|---|---|---|
| Направление «вперёд» | **+Z** (нос смотрит в +Z) | игра ставит `mesh.rotation.set(0, hdg, 0)`, где `hdg = atan2(F.x, F.z)` |
| Верх | +Y | |
| Начало координат | центр болида, **y = 0 — это уровень асфальта** | игра ставит `mesh.position.set(x, 0, z)` |

Если перепутать ось «вперёд» — болиды поедут боком. Если сместить y — провалятся под трассу или повиснут.

### 3.2. Размеры и посадка (сохранять, иначе поедет физика и вид из кокпита)

| Что | Значение |
|---|---|
| Габарит днища | ширина **1.8**, длина **5.0**, центр в z = 0 |
| Радиус колеса | **0.5** (центр колеса на y = 0.5 → колесо касается земли) |
| Ширина колеса | ~0.42 (перед), можно чуть шире сзади |
| Передние колёса | x = **±1.05**, z = **+2.0** |
| Задние колёса | x = **±1.05**, z = **−1.7** |
| Максимальная высота | ~**1.4** (не выше, иначе лезет в камеру и в габариты) |

Ширину колеи и колёсную базу менять **нельзя** — они завязаны на ощущение габарита и на камеру.
Пропорции кузова между колёсами — можно и нужно дорабатывать.

### 3.3. userData — обязательный интерфейс анимации

Группа обязана вернуть:

```js
g.userData = { frontWheels, wheels, sw };
```

- **`frontWheels`** — массив из 2 групп передних колёс. Каждый кадр игра делает
  `w.rotation.y = c.steerVis` → это поворот руля. Поэтому колесо надо собирать **вокруг локального нуля
  своей группы**, ось вращения колеса — по X.
- **`wheels`** — массив всех 4 групп колёс.
- **`sw`** — группа рулевого колеса (**только при `simple === false`**, иначе `null`).
  Игра делает `sw.rotation.z = -player.steerVis * 1.7`.
  Текущее положение: `sw.position.set(0, 0.8, 0.5)`, `sw.rotation.x = -0.62`.

Если `userData` не отдать — пропадёт поворот колёс и анимация руля.

### 3.4. Вид из кокпита (критично)

Камера кокпита стоит **на y = 1.42, на 0.62 позади центра болида**, и смотрит вперёд (+Z) на высоту y ≈ 1.18.

Из этого следует:
- ничто не должно перекрывать обзор вперёд по этой линии (гало — тонкое, дуга не должна закрывать центр);
- **рулевое колесо должно быть видно** в нижней части кадра (сейчас на `(0, 0.8, 0.5)`);
- капот/воздухозаборник за спиной пилота обзор не мешают.

Проверять обязательно: в крутилке есть ракурсы, но лучше отдельно поставить камеру в эту точку и посмотреть.

### 3.5. Прочие детали, завязанные на игру

- **Табличка с номером**: плоскость 0.5×0.5 на `(0, 1.12, -1.4)`, `rotation.y = Math.PI`,
  текстура генерируется функцией `numTex(num, colorHex)` — только при `simple === false`.
- **Тень**: плоскость 3.6×4.9 на y = 0.06, `rotation.x = -PI/2`, `renderOrder = 2`,
  материал с общей текстурой `ENVSHADOW`, `depthWrite: false`. Оставить.
- **Цвет**: кузовные детали красятся `colorHex`. Всё остальное (карбон, резина, гало, шлем) —
  фиксированные материалы.

### 3.6. Что отключает `simple === true` (LOD для 21 болида ИИ)

Сейчас отключаются: ступицы и спицы в колёсах, рычаги подвески, табличка с номером, зеркала,
приборная панель, рулевое колесо. Логику LOD сохранить: **у ИИ должно быть заметно меньше геометрии**.

## 4. Производительность (главное ограничение)

На трассе одновременно **22 болида**. Слабое звено — старый iPad 5.

Ориентиры:
- у болида **игрока** — примерно до 3000 треугольников;
- у болида **ИИ** (`simple`) — примерно до 1200 треугольников;
- сегментов у скруглённых примитивов — **8–16, не больше** (`CylinderGeometry(r, r, h, 12)` достаточно);
- избегать: полупрозрачных наложений, множества уникальных материалов, очень мелких деталей,
  которые не видны с игровой камеры.

**Про merge (объединение геометрии).** При встраивании в игру статичные детали будут склеены
в один меш на материал (кузов / карбон / тёмные детали), чтобы видеокарта рисовала болид за
~5 вызовов вместо ~40. Форма, вершины и тени при этом сохраняются полностью — визуально 1-в-1,
«плоско» не станет. Колёса и руль остаются отдельными группами, потому что вращаются.

Что от этого требуется модели: **детали одного материала должны быть отдельными мешами внутри группы**
(не объединять вручную), и не плодить уникальные материалы сверх нужного — иначе merge даст мало выигрыша.

## 7. Что вернуть в основной чат

1. **Файл `car-preview.html`** с финальной моделью (крутилка целиком).
2. Внутри него — функция сборки болида, желательно самодостаточная, вида
   `buildCar(primaryHex, accentHex, simple)`, возвращающая `THREE.Group` с корректным
   `userData = {frontWheels, wheels, sw}`.
3. Подтверждение, что соблюдены: направление **+Z вперёд**, начало координат на уровне земли,
   радиус колеса 0.5, позиции колёс (±1.05; +2.0 / −1.7), высота ≤ ~1.4.
4. Если что-то из контракта пришлось нарушить — явно перечислить что и почему.

После этого в основном чате: смотрим крутилку → объединяю геометрию по материалам (merge) →
встраиваю в игру вместо текущей `makeCar` → проверяю вид из кокпита, вид за болидом,
поворот колёс, анимацию руля, LOD у ИИ и производительность.
