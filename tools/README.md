# tools/ — регрессионные пробники APEX '26

Прогоняют чек-лист из CLAUDE.md §13, не открывая браузер. **`index.html` только
читается и никогда не меняется.**

## Запуск

```
cd tools && npm install     # один раз: ставит three@0.128.0
node run-all.js             # весь чек-лист, ~3 минуты
```

Из корня репозитория то же самое: `node tools/run-all.js`.
Код возврата 0 — всё сошлось, 1 — что-то не сошлось, 2 — пробник упал.

```
node run-all.js --list                  показать имена пробников
node run-all.js --only=pole,grid        прогнать только эти
node run-all.js --trace                 полный стек, если пробник упал
node probe-pole-times.js                любой пробник — сам по себе
APEX_INDEX=~/архив/1.15.14.html node run-all.js     прогнать по другой сборке
```

Последнее удобно для сверки с архивной сборкой: у владельца сохранена каждая
отданная версия, и разницу в поведении можно померить, а не угадать.

## Что прогоняется

| Ключ | Пробник | Что проверяет |
|---|---|---|
| `pole` | `probe-pole-times.js` | Времена поула — каждая трасса × 3 режима против таблицы CLAUDE.md §4, до тысячной |
| `quali` | `probe-quali-spread.js` | Разброс квалификации: ширина ±0.2 % и симметрия, слабый в топ-6 и лидер ниже P11 — 0 % |
| `race` | `probe-race-finish.js` | Гонка добегает до конца на всех трассах |
| `outro` | `probe-outro-autopilot.js` | Автопилот после финиша: 0 кадров вне трассы из 220 + выпуск с 12 прямых |
| `overtake` | `probe-start-overtake.js` | Объезд стоящего на старте: 11 из 11 за 25 с, три зерна |
| `startsync` | `probe-start-sync.js` | Никто не трогается раньше погасания фонарей и раньше своей реакции |
| `grid` | `probe-grid.js` | Решётка: 22 из 22, стороны чередуются, отступ каждого совпадает с расчётным, разметка на асфальте стоит там же, где болид |
| `wall` | `probe-wall-kinks.js` | Изломы отбойника: ни одного больше 75° |
| `materials` | `probe-materials.js` | Нет мешей с текстурой без UV и с `vertexColors` без атрибута цвета |
| `load` | `probe-scene-load.js` | Меши сцены (Монца 43, Сильверстоун 46), бюджеты болидов, вызовы отрисовки |
| `print` | `probe-track-fingerprint.js` | Отпечаток каждой существующей трассы: старые трассы не сдвинулись ни на сантиметр |

Главный из них — `pole`. Он ловит непреднамеренные изменения физики лучше
остальных: расхождение даже в тысячную означает, что баланс поехал.

## Добавление новой трассы (08.2026)

Пробники **сами перебирают все трассы** из `TRACKS` — через `H.tracks()`
(все) и `H.tracks(true)` (только видимые в меню, для долгих гоночных
пробников). Жёстких «с 0 по 3» в них больше нет: новая трасса автоматически
попадает под весь чек-лист, и забыть её невозможно.

Эталоны, привязанные к имени трассы (таблица поулов, бюджет мешей, отпечаток),
для незнакомой трассы не заваливаются, а печатают измеренное как заметку —
готовые числа для записи. Разошёлся эталон **старой** трассы — это провал,
и он означает ровно одно: правка общего кода дотянулась туда, куда не должна.

Порядок такой:

1. Новая трасса дописывается **в конец** `TRACKS` с `hidden:true` — индексы
   старых не сдвигаются, в меню её ещё нет.
2. Полный прогон. Старые трассы обязаны совпасть: 12 клеток поулов до
   тысячной и отпечаток до сантиметра.
3. Числа новой трассы из заметок переносятся в эталоны, `hidden` снимается.

Правка **общего** кода (строители отбойника, зон вылета, трибун, кромок,
`buildWidth`) ради новой трассы — отдельное осознанное решение: она достанется
и Монце с Сильверстоуном. Пробник `print` покажет, что именно сдвинулось;
если сдвиг намеренный, его числа переписываются, а причина пишется в CLAUDE.md.

**Автотесты не заменяют проверку на устройстве владельцем.** Они меряют числа,
а не ощущение игры.

## Как это устроено

`harness.js` делает всё, на чём держатся пробники:

1. Из `index.html` вынимается **только игровой скрипт** — тот из двух инлайновых,
   в котором есть `function makeTrack`. Второй (сам three.js) не нужен: библиотека
   берётся из npm, версия `0.128.0` — ровно та, что вшита в файл.
2. Собирается заглушка браузера: `document` с поиском и созданием элементов
   (включая `canvas` с 2D-контекстом), `window`, `addEventListener`,
   `performance.now`, `requestAnimationFrame` / `cancelAnimationFrame`,
   `setTimeout` с немедленным вызовом.
3. `THREE.WebGLRenderer` подменяется объектом-пустышкой: картинка не нужна,
   нужны только расчёты.
4. Скрипт выполняется в отдельном контексте `vm`. Верхние `let` и `const` такого
   скрипта видны следующим вызовам в том же контексте — это и есть доступ ко
   всем внутренностям игры: `track`, `player`, `field`, `update`, `estLapTime`,
   `gridSpot`, `project` и прочему. Ничего экспортировать из `index.html`
   не потребовалось.
5. `Math.random` подменяется линейным конгруэнтным генератором с зерном, чтобы
   заезды повторялись от прогона к прогону.

Полезные функции `harness.js`:

| | |
|---|---|
| `loadGame({seed})` | загрузить игру, вернуть окружение |
| `env.evalIn(код)` | выполнить код внутри игры и вернуть результат |
| `setupWorld(env,{trackIdx})` | построить только мир трассы, без болидов |
| `setupWeekend(env,{trackIdx,diff,laps})` | штатный `startWeekend` до начала квалификации |
| `startRaceAt(env, поз)` | собрать решётку с игроком на позиции 1…22 и стартовать |
| `lightsOut(env)` | погасить фонари сразу, не отматывая пятисекундную последовательность |
| `noRetirements(env)` | отменить запланированные сходы |
| `env.timeouts.mode` | `'immediate'` (по умолчанию) или `'defer'` — см. ниже |

### Автопилот игрока

Живёт внутри игры (`__AP` в `harness.js`): проецирует машину на трассу, смотрит
вперёд на несколько точек, доворачивает к осевой и тормозит по максимальной
кривизне впереди. Кадры крутит `__drive(n, dt, режим)`, где режим `'auto'` —
автопилот рулит, `'idle'` — руки прочь (нужно пробнику про стоящего на старте).

Он нужен только чтобы провезти болид по кругу. Автопилот **после финиша** —
это код самой игры (ветка `qualiOutro||raceOutro` в `update`), и пробник `outro`
проверяет именно его, а не наш.

### Про `setTimeout`

По умолчанию заглушка вызывает функцию немедленно. Игре это не мешает нигде,
кроме одного места: `finishRace()` ставит трёхсекундный таймер закрытия заезда,
и при немедленном вызове заезд закрывается той же строкой, что его начала —
автопилот после финиша не успевает поработать. Поэтому пробник `outro`
переключает `env.timeouts.mode = 'defer'`: таймеры копятся, а
`env.runTimeouts()` запускает их по требованию.

## Оговорки

* **Изломы отбойника** считаются только по стыкам видимой ленты. Разрывы, где
  ленты нет, закрыты прямыми перемычками (`wallBridges`) — их стыки с лентой
  резкие специально: настоящий барьер идёт мимо шиканы, а не повторяет её.
  Углы этих стыков печатаются, но в зачёт не идут.
* **Сузука и Монако** скрыты из меню, барьер у них строится обобщённой
  `buildWallProfile` без разметки настоящей линии, и лента складывается до 178°.
  Пробник это печатает, но по ним не заваливается: известное ограничение
  (CLAUDE.md §8 п.2, §9).
* **Автопилот после финиша** при свободном выпуске с прямой выносит болид за
  кромку: Монца и Монако 0 м, Сузука до 4.4 м, Сильверстоун до 8.7 м (Club).
  Порог пробника — 12 м; это измеренное поведение сборки, а не поломка.
* Времена поула считаются `estLapTime` без случайного разброса квалификации
  (±0.2 %), который есть в живой игре. Эталон в CLAUDE.md записан по
  чистому расчёту, и пробник сверяется с ним. За самим разбросом следит
  отдельный пробник `quali` — до 08.2026 его не проверял никто.

## Проверено, что пробники ловят

Каждый пробник прогонялся по намеренно испорченной копии `index.html`
(через `APEX_INDEX`, оригинал не трогался) и заваливался как надо:

| Поломка | Кто ловит |
|---|---|
| `DIFF_MUL.normal` 0.90 → 0.91 | `pole` |
| разброс квалификации ±0.2 % → −0.4…+0.6 % (сборка 1.15.16 и раньше) | `quali` |
| разброс квалификации ±0.2 % → ±0.02 % (промах разрядом) | `quali` |
| разброс той же ширины, но со смещением (−0.1…+0.3 %) | `quali` |
| финиш не засчитывается | `race` |
| у автопилота финиша отключён руль | `outro` |
| у автопилота финиша отключён тормоз | `outro` |
| ИИ не выезжает из-за медленного впереди | `overtake` |
| ИИ не ждёт своей реакции на старте | `startsync` |
| `GRID_GAP` 8 → 9 | `grid` |
| полоса решётки `0.45` → `0.60` | `grid` |
| игрок ставится по ближайшему индексу, а не по непрерывной координате | `grid` |
| разметка клеток рисуется по ближайшему индексу (сборка 1.15.15: Монца и Монако — 4 м) | `grid` |
| зигзаг отбойника на 3 м | `wall` |
| склейка теряет UV | `materials` |
| склейка теряет вершинные цвета | `materials` |
| в сцену добавлен лишний меш | `load` |
| ширина кромки (общий код) 0.9 → 0.95 м | `print` — все четыре трассы |
| порог «складывания» полотна −0.77 → 0.2 (общий код) | `print` — Сузука: ширина, отбойник, геометрия |
| обобщённый отступ отбойника `min(runoff,14)` → `12` | `print` — Сузука (единственная на этой ветке кода) |

Отдельно проверено обратное: **дописанная пятая трасса** (фиктивная, `hidden:true`)
все 11 пробников оставляет зелёными, отпечаток четырёх старых трасс не шевелится,
и при этом новая трасса сама попадает в `race`, `outro`, `grid`, `wall`,
`materials`, `load` и `print`.

Одна правка отпечатком **не** ловится: `slope` 0.12 → 0.13 в `buildWidth`.
Не изъян пробника — на нынешних трассах эта ветка кода спит: сумма профиля
полуширины у Монцы, Сильверстоуна и Сузуки в точности равна `M × полуширина`,
то есть сужения нет вообще, а у Монако оно 1.15 м на весь круг.
